[h1]ApocalipseBR LoadGridSquare Optimizations[/h1]

Three independently enabled Build 42 patches that reduce Lua work as map chunks load.

[h2]LiuDing Tiles[/h2]
\common\media\lua\server\Items\LiuDing3DItem.lua Converts the [b]LiuDing_Tiles_3DItem_0[/b] map marker into a real sledgehammer. The converter runs when the marker loads, checks the surface height on that square, and places the item above furniture where applicable.

Mod ID [b]ApocalipseBR_LiuDingTiles_fix[/b]. Requires [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3736154771]LiuDing Tiles[/url] (mod ID [b]LiuDing_Tiles[/b]).

[h2]True Swimming[/h2]
\42\media\lua\shared\TrueSwimmingShared.lua Removes orphaned invisible pontoons that can be left behind by an interrupted session or arrive in a streamed multiplayer chunk. Cleanup runs when the [b]TrueSwimming_ponton[/b] sprite loads. True Water's shallow-water setup still uses its square-load handler because it checks water properties and neighboring squares.

Mod ID [b]ApocalipseBR_TrueSwimming_fix[/b]. Requires [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3802372726]True Swimming by Harkwood[/url] (mod ID [b]TrueSwimming[/b]). The patch is based on True Swimming 1.9.

[h2]MinidoracatBuilder[/h2]
This companion patch for [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3830045886]Minidoracat Build Anything for B42[/url] by Minidoracat replaces the builder's placement module. The original hook entered Lua for each nonempty square as chunks loaded. The replacement receives one [b]LoadChunk[/b] callback per chunk and queues discovery when needed. A cursor spreads square and special-object visits across ticks and can resume within a dense square. All chunks share a cap of 256 scan steps per tick. Deferred repair jobs share a cap of eight per tick. Both queues share a 2 ms time target checked between steps.

The server or single-player save remembers completed scans by chunk coordinate in GlobalModData. An index entry must match a marker saved with the chunk itself. This guards against using a cache from a different chunk save. A verified chunk with no candidates skips the cursor entirely. A verified chunk with candidates visits only their recorded squares to apply current sandbox settings and, in single-player, register light switches. Placement, removal, and moved door leaves invalidate affected chunks. Failed or blocked repairs remain eligible, so an overlay waiting for its host can be tried on a later load. Multiplayer clients keep the bounded discovery scan because a streamed chunk can change while a client is away.

Moving work off the load callback creates a window where loaded objects can still have their saved zombie protection, container capacity, corner or floor flags, or lighting state. When the cursor changes pathing flags it refreshes the affected square. The builder checks for an unmigrated floor refund before calculating dismantle materials, so that interaction can complete the transfer ahead of the cursor. Eligible floors retain their legacy materials until the refund entry is confirmed. The overlay repair likewise verifies the attachment and its refund record before removing the old object.

The cache resets when either mod's reported version or the patch's migration revision changes. If version metadata is missing, the migration revision still applies. In single-player, or as a server admin in multiplayer, right-click the world and select [b]Reset Builder Migration Cache[/b] to clear all coordinate entries. Loaded chunks observed by the cache are requeued through the same tick budget, and other chunks are checked on their next load. The reset affects only the index. Floor and overlay refund ledgers are kept. Use it after changing the save while this companion patch was disabled.

Mod ID [b]minidoracatbuilderfix[/b]. Requires mod ID [b]MinidoracatBuilderFor42[/b] and game Build [b]42.22.2[/b] or later. The override is based on MinidoracatBuilder [b]42.22.2-1.1.1[/b]. Enable both mods on the server and clients for multiplayer. Check compatibility after updating the original mod because this patch replaces its placement file.

[h2]How the sprite-specific patches work[/h2]
The old LiuDing Tiles and True Swimming handlers ran through [b]Events.LoadGridsquare[/b] and scanned objects in Lua on each loaded square. With [b]MapObjects.OnLoadWithSprite[/b], the engine matches the registered sprite name and passes that object directly to Lua. Ordinary squares skip both patched Lua handlers. When LoadGridSquare is used to find an specific object, this change has the potential to reduce millions of LoadGridSquare hook calls during a server runtime and coalesce into a single OnLoadWithSprite hook call. The engine still traverses square objects, and LiuDing still checks the surface when it finds a marker. The savings come from fewer Lua calls and fewer Lua-to-Java object lookups during chunk loading.

MinidoracatBuilder uses Events.LoadChunk to reduce Java-to-Lua callbacks and a tick budget to spread the square and object scan across frames.
